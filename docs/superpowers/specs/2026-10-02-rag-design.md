# المرحلة 3: RAG، الشات بيرد من ملفات الجمعية — Design Spec

- **التاريخ:** 2026-10-02
- **الحالة:** المطوّر فوّض القرارات زي المرحلة 2، ووافق إننا نجرّب موديل `granite-embedding:278m`. المراجعة هتبقى في الآخر.
- **مبني على:** المرحلة 1 (`2026-10-02-ai-chat-design.md`) والمرحلة 2 (`2026-10-02-tickets-design.md`).

## 1. الهدف

- **ليه:** نتعلم RAG: الـ embeddings، والبحث بالمعنى (vector search)، وتقسيم المستندات، وإزاي نحط النتايج في الـ prompt.
- **المشكلة:** معلومات الجمعية مكتوبة كفقرة ثابتة في `charity-prompt.ts`. والموديل بيألّف لما السؤال يبقى برّه المعلومات دي (في المرحلة 1 جاوب على سؤال كاس العالم بإجابة متألّفة).
- **إيه:** معلومات الجمعية تتنقل لملفات Markdown في فولدر `knowledge/`. ومع كل رسالة، السيرفر بيدوّر على أقرب 3 أجزاء للسؤال ويبعتهم للموديل، والموديل يرد منهم بس.
- **النجاح معناه:**
  1. لما الأسئلة تبقى برّه الجمعية (كاس العالم، كيكة، عاصمة فرنسا)، الموديل يرد بجملة الرفض الثابتة بلغة السؤال.
  2. أسئلة الجمعية بالعربي والإنجليزي ترد من الملفات.
  3. لما تعدّل ملف في `knowledge/` وتعيد تشغيل السيرفر، الإجابات تتغيّر، والأجزاء اللي متغيّرتش متتعملهاش embedding تاني.
  4. تحت كل رد فيه سطر صغير بيقول **الأجزاء اللي السيستم قراها**، علشان تتعلم وتشوف إيه اللي بيحصل.
  5. لو موديل الـ embeddings مش متنزّل أو Ollama مقفول، الشات يرجّع 503 والـ log يقول تعمل إيه. ولما تصلّح المشكلة، الشات يرجع يشتغل **من غير restart**.
  6. `npm test` ينجح من غير Ollama.

## 2. نتايج التجربة (spike) اللي القرارات مبنية عليها

| التجربة | النتيجة |
|---|---|
| `granite-embedding:278m` (562MB، 768 بُعد) على 14 سؤال عربي/مصري/إنجليزي و5 أجزاء | الجزء الصح طلع **الأول في 11 من 14**، وكان **ضمن أول 2 في الـ 14 كلهم** |
| هل الـ score لوحده يفرّق الأسئلة اللي برّه الجمعية؟ | **لا.** أقل score لسؤال حقيقي كان 0.599، وأعلى score لسؤال برّه الجمعية كان 0.664، فمفيش threshold ينفع |
| `qwen2.5:3b` بأقرب أجزاء وجملة رفض ثابتة | رفض الـ 3 أسئلة اللي برّه الجمعية. واحد منهم كان سؤال عربي، والرفض جه بالإنجليزي |
| مصدر بيقول "الجمعة والسبت إجازة" | الموديل قال "مفتوحة يوم الجمعة". ولما المصدر بقى "الجمعة: مقفول." رد صح |
| سؤال إنجليزي والمصدر عربي بس | الموديل رفض يرد، مع إن المعلومة موجودة |

**اللي طلع من التجربة:**
- هنجيب أقرب 3 أجزاء، ومن غير threshold.
- الرفض مسؤولية `qwen` بجملة ثابتة.
- ملفات المعرفة تتكتب **بشكل صريح** (سطر لكل معلومة)، و**بالعربي والإنجليزي** في كل جزء.

## 3. برّه النطاق

- صفحة يعدّل منها الموظفين ملفات المعرفة (الملفات بتتعدّل في الـ repo).
- إن الفهرس يتحدّث وقت ما الملف يتغيّر والسيرفر شغال (التحديث بيحصل مع الـ restart).
- سكريبت لقياس جودة البحث (ممكن يبقى تمرين بعدين).
- رفع ملفات PDF أو Word.
- إننا نعرض المصدر جوه الرد نفسه (citations جوه النص).

## 4. القرارات

| القرار | الاختيار |
|---|---|
| موديل الـ embeddings | `granite-embedding:278m` عن طريق `POST {OLLAMA_URL}/api/embed` بـ `{ model, input: string[] }`، وبيرجّع `{ embeddings: number[][] }`. الاسم بيتغيّر بـ `OLLAMA_EMBED_MODEL`. |
| مكان المعرفة | `knowledge/*.md` في جذر المشروع، ويتغيّر بـ `KNOWLEDGE_DIR`. |
| التقسيم | كل `## عنوان` بيبدأ جزء جديد، والجزء بيبقى العنوان والنص اللي تحته. وأي حاجة قبل أول `##` (زي `# عنوان الملف`) بتتجاهل. |
| تخزين الـ vectors | جدول `knowledge_chunks` في SQLite، والـ embedding بيتخزّن BLOB (بايتات `Float32Array`). |
| إعادة الفهرسة | لكل جزء `content_hash` (sha256 للعنوان والنص والموديل). وقت الفهرسة، الأجزاء اللي الـ hash بتاعها اتغيّر بس هي اللي بتتعملها embedding، والأجزاء اللي اتشالت من الملفات بتتمسح. |
| امتى الفهرسة | Lazy مع أول بحث، والنتيجة بتتحفظ (memoized promise). ولو فشلت، الـ promise بيتمسح، فالطلب اللي بعده يحاول تاني. |
| البحث | cosine similarity في JavaScript على كل الأجزاء، ونرجّع أقرب 3. ده مناسب لأن الأجزاء أقل من 100. |
| نص البحث | آخر رسالة من العميل. ولو أقل من 20 حرف (بعد `trim`) وفيه رسالة قبلها من العميل، بنحط الاتنين مع بعض: الرسالة القديمة، وبعدها سطر جديد، وبعدها الأخيرة. ده علشان أسئلة المتابعة زي "وبالفيزا؟". |
| الـ prompt | `buildSystemPrompt(sources)` بيرجّع القواعد، وبعدين `SOURCES:` وتحتها `[n] عنوان\nنص` لكل جزء. ولو مفيش أجزاء، بيكتب `(none)`. والفقرة الثابتة القديمة بتتشال. |
| جملة الرفض | عربي: `معنديش المعلومة دي. أقدر أساعدك في أي سؤال عن جمعية الخير، أو كلّمنا على 0100 000 0000.` — إنجليزي: `I don't have that information. I can help with questions about Al-Khair Foundation, or call us on 0100 000 0000.` |
| SSE | event جديد `{"type":"sources","sources":[{"title","file"}]}` بيتبعت **قبل** أول token. |
| الواجهة | تحت رد الـ assistant يظهر سطر صغير: `اتقرا من: <عنوان>، <عنوان>`. وده مش citations، ده بيوضّح الأجزاء اللي السيستم قراها. |

## 5. شكل ملفات المعرفة

مثال (`knowledge/donations.md`):

```markdown
# التبرع / Donating

## طرق التبرع / How to donate
- فودافون كاش: 0100 000 0000
- تحويل بنكي: حساب "جمعية الخير" رقم 000123456789
- نقدي أو تبرعات عينية (هدوم، أكل): في المقر في مواعيد الشغل
- Vodafone Cash: 0100 000 0000
- Bank transfer: "Al-Khair Foundation", account 000123456789
- Cash or goods (clothes, food): at the office during opening hours
```

**الملفات:**
- `about.md`: العنوان، ومواعيد الشغل (كل يوم في سطر صريح)، والتواصل.
- `donations.md`: طرق التبرع، وإيصال التبرع.
- `volunteering.md`: الأنشطة، وإزاي تتطوع، والسن.
- `help-requests.md`: الأوراق المطلوبة، وبعد التقديم بيحصل إيه، وأنواع المساعدة.

المعلومات نفسها هي نفس معلومات المرحلة 1، مكتوبة بالشكل ده.

## 6. الداتابيز

```sql
CREATE TABLE IF NOT EXISTS knowledge_chunks (
  id INTEGER PRIMARY KEY,
  file TEXT NOT NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  content_hash TEXT NOT NULL UNIQUE,
  embedding BLOB NOT NULL
);
```

## 7. الأخطاء

| المشكلة | اللي هيحصل |
|---|---|
| موديل الـ embeddings مش متنزّل (Ollama بيرجّع 404 أو خطأ فيه "not found") | الشات يرجّع `503`، والـ log يقول: `Embedding model "granite-embedding:278m" is not downloaded. Run \`ollama pull granite-embedding:278m\`.` |
| Ollama مقفول وقت الفهرسة أو البحث | `503`، والطلب اللي بعده يحاول تاني. |
| فولدر `knowledge/` مش موجود أو فاضي | تحذير في الـ log، والبحث بيرجّع `[]`، والموديل بيرفض كل حاجة بجملة الرفض. |
| ملف من غير أي `##` | الملف بيتجاهل، ومعاه تحذير في الـ log. |

## 8. الاختبارات

- **السيرفر** (من غير Ollama):
  - التقسيم.
  - تحويل `Float32Array` لـ BLOB وبالعكس.
  - الـ cosine.
  - نص البحث (أسئلة المتابعة).
  - `KnowledgeBase`:
    - بيفهرس بـ embed وهمي.
    - مش بيعمل embedding تاني للجزء اللي متغيّرش.
    - بيمسح الأجزاء اللي اتشالت.
    - ترتيب النتايج صح.
    - بيحاول تاني بعد الفشل.
    - الفولدر الفاضي مش بيعمل مشكلة.
  - `buildSystemPrompt`.
  - الـ `sources` event بيتبعت قبل أول token.
  - `503` لما البحث يفشل.
  - Ollama embedder: الطلب، و404 بيطلّع رسالة `ollama pull`.
- **Angular:**
  - الـ parser بيقرأ `sources`.
  - `ChatService` بيحط `sources` على رسالة الـ assistant.
  - الشات بيعرض "اتقرا من".
  - `ChatService` بيبعت للسيرفر `role` و `content` بس.
- **تجربة حقيقية:**
  - نفس أسئلة الـ spike في الشات الحقيقي: 3 أسئلة برّه الجمعية لازم تترفض، وسؤال الجمعة، وسؤال الإيصال بالإنجليزي.
  - نعدّل ملف ونعمل restart، ونتأكد إن الجزء ده بس اللي اتعمله embedding تاني.

## 9. تعديل بعد التجربة الحقيقية (Task 5)

التجربة الحقيقية بعد التنفيذ كشفت إن `qwen2.5:3b` لوحده مش بيلتزم بالقواعد بشكل ثابت:
- جاوب "Paris" على سؤال عاصمة فرنسا.
- رد بالعربي على سؤال إنجليزي.
- مرة رد بالصيني.

جرّبنا كذا ترتيب للـ prompt وكذا temperature، وأحسن نتيجة كانت **9 من 15** بس.

**الحل:** القرارات المهمة بقت تتعمل في الكود أو في خطوة منفصلة، مش جوه الرد.

| الإضافة | التفاصيل |
|---|---|
| **فحص الموضوع (topic gate)** | طلب منفصل لـ `qwen2.5:3b` ومعاه `format: { about_foundation: boolean }` و `temperature: 0`، والـ prompt فيه مواضيع الجمعية وأمثلة. نص الفحص هو نفس نص البحث (§4). |
| **لو `false`** | الكود بيبعت `sources: []`، وبعدها جملة الرفض بلغة السؤال كـ token واحد، وبعدها `done`، والموديل مش بيكتب. |
| **لو الفحص نفسه فشل** | نكمّل عادي (fail-open) ونكتب في الـ log `[chat] topic check failed: …`، والقاعدة اللي في الـ prompt بتفضل موجودة كاحتياطي. |
| **اللغة** | `detectLanguage(text)`: لو فيه أي حرف عربي (U+0600–U+06FF) يبقى `ar`، غير كده `en`. والـ prompt بيقول للموديل لغة واحدة بس: عربي "Reply in Arabic script only…"، وإنجليزي "Reply in English only.". والرفض في الـ prompt بقى جملة واحدة بلغة السؤال. |
| **temperature الرد** | `0.2` (كانت الافتراضي بتاع Ollama). |
| **التوازي** | الفحص والبحث بيشتغلوا مع بعض (`Promise.all`). |

**نتيجة التجربة بعد التعديل:** 10 أسئلة واتكرروا 3 مرات. الفحص طلع **30 من 30**، والإجابات **14 من 15**، ومتوسط وقت الفحص حوالي 470ms.
