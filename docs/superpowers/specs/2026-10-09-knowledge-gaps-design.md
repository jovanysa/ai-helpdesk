# الأسئلة اللي مالهاش إجابة (Knowledge Gaps) — Design Spec

- **التاريخ:** 2026-10-09
- **الحالة:** المطوّر اختار الميزة، وفوّض القرارات زي المراحل اللي فاتت، والمراجعة هتبقى في الآخر.
- **مبني على:** المرحلة 3 (`2026-10-02-rag-design.md`)

## 1. الهدف

لما الشات ميعرفش يجاوب، السؤال يتسجّل. والموظفين يشوفوا الأسئلة دي في صفحة، ويضيفوا إجاباتها في `knowledge/`، فالشات يكمّل مع الوقت.

**النجاح معناه:**
1. أي رد بيقول فيه الشات إن المعلومة مش موجودة بيتسجّل، ومعاه السؤال والرد. والتسجيل مش بيبطّأ الشات.
2. الأسئلة اللي خطوة الفحص رفضتها على إنها برّه الجمعية بتتسجّل في قايمة منفصلة. ده علشان الموظف يلاحظ لو الفحص رفض سؤال صح بالغلط (زي الركنة أو الفرانكو).
3. صفحة `/staff/gaps` محمية بالـ login، وفيها:
   - الأسئلة متجمّعة، والأكتر تكرارًا فوق.
   - لكل سؤال: عدد المرات، وآخر مرة اتسأل، وآخر رد قاله الشات.
   - زرار "تم" بيخفي السؤال.
4. لو سؤال اتعمله "تم" واتسأل تاني، بيرجع يظهر وبيبدأ عدّه من الأول.
5. لو الفحص بعد الرد فشل (Ollama مقفول)، مفيش حاجة بتبوظ: الشات شغال عادي، والسؤال ببساطة مش بيتسجّل، ومعاه سطر في الـ log.
6. `npm test` ينجح من غير Ollama.

## 2. نتايج التجربة (spike)

| التجربة | النتيجة | القرار |
|---|---|---|
| فحص بعد الرد: `qwen2.5:3b` بيرد بـ JSON `{ missing_information }` على 14 رد (5 "مش عارف" بصيغ مختلفة، و9 إجابات منهم "لأ" وتحية)، واتكرروا مرتين | **28/28**، وحوالي 0.7 ثانية | نستخدمه، ويشتغل **بعد** ما الـ stream يخلص (fire-and-forget) |
| تجميع الأسئلة بالـ embeddings (`granite`) | "مصاريف الجامعة" و"مصاريف المدرسة" خدوا **0.94**، و"credit card" و"فيزا" خدوا **0.558** | مفيش threshold بيفرّق صح، فـ**مش هنستخدم embeddings للتجميع** |

**التجميع:** بالنص بعد ما نوحّده (`normalizeQuestion`):
1. `trim` وتحويل لـ lowercase.
2. شيل التشكيل والتطويل (ـ).
3. توحيد الحروف: أ/إ/آ ← ا، وى ← ي، وة ← ه.
4. شيل علامات الترقيم (ومنها ؟ و ،).
5. دمج المسافات.

## 3. برّه النطاق

- تجميع الأسئلة بالمعنى (اتجرّب وفشل، شوف §2).
- إن الموظف يكتب الإجابة من الصفحة نفسها ويتضاف للمعرفة. ده ميزة "تعديل المعرفة من صفحة"، وممكن تتعمل بعدين.
- إشعارات للموظفين.
- إخفاء البيانات الشخصية من الأسئلة. الصفحة للموظفين بس، وده هيتكتب كملاحظة.

## 4. التصميم

**الداتابيز:**

```sql
CREATE TABLE IF NOT EXISTS unanswered_questions (
  id INTEGER PRIMARY KEY,
  question TEXT NOT NULL,
  question_key TEXT NOT NULL,      -- normalizeQuestion(question)
  reply TEXT NOT NULL,
  reason TEXT NOT NULL CHECK (reason IN ('no_answer','off_topic')),
  created_at TEXT NOT NULL,
  resolved_at TEXT
);
CREATE INDEX IF NOT EXISTS unanswered_open ON unanswered_questions (reason, resolved_at, question_key);
```

**مين بيسجّل:**
- **`off_topic`:** لما خطوة الفحص ترفض السؤال، بيتسجّل على طول ومعاه جملة الرفض.
- **`no_answer`:** بعد ما الرد يخلص بـ `done`، بنعمل فحص `missing_information`. ولو `true`، بيتسجّل.
- **مش بيتسجّل:** لو الرد اتوقف (المستخدم داس "إيقاف" أو قفل الصفحة)، أو حصل خطأ في النص، أو الرد كان فاضي.

**السؤال اللي بيتسجّل:** آخر رسالة من العميل (`current`)، مش النص المدموج اللي بنستخدمه في البحث.

**`GapRecorder`** (interface للـ chat handler): فيه `recordOffTopic(question, reply)` و `reviewReply(question, reply)`. والاتنين **مبيرموش exception خالص**، وأي خطأ بيتكتب في الـ log بس:
- `[gaps] could not record question: …`
- `[gaps] answer check failed: …`

**الـ API** (للموظفين بس، وبنفس جدول الـ routes بتاع `api-routes.ts`):

| Method و Path | الرد |
|---|---|
| `GET /api/gaps?reason=no_answer\|off_topic` | `200 GapGroup[]`. الافتراضي `no_answer`، ومرتّبة بالعدد من الأكبر، وبعدها آخر مرة اتسأل من الأحدث. |
| `POST /api/gaps/resolve` | Body: `{ reason, key }`، بيرجّع `200 { resolved: n }`، وبيحط `resolved_at` لكل الصفوف المفتوحة في المجموعة دي. |

`GapGroup` = `{ key, question (آخر صيغة اتسأل بيها), count, lastAskedAt, lastReply }`

**الواجهة:**
- **في `/staff`:** في الـ header لينك "أسئلة مالهاش إجابة".
- **صفحة `/staff/gaps`** (lazy، وعليها `authGuard`، و `RenderMode.Client` لأنها تحت `staff/**`):
  - تبويبين: "معندوش المعلومة" و "اترفضت كبرّه الجمعية".
  - كل مجموعة فيها: السؤال، وعدد المرات (`×N`)، وآخر مرة، وآخر رد في `<details>`، وزرار "تم".
  - لو مفيش أسئلة: "مفيش أسئلة مفتوحة 🎉".
  - تحت الصفحة سطر: "أضف الإجابة في ملفات knowledge/ واعمل restart للسيرفر، وبعدين دوس تم."

## 5. الاختبارات

- **السيرفر:**
  - `normalizeQuestion` (همزات، ة/ه، ؟، مسافات، إنجليزي).
  - الـ repository: التجميع والترتيب، و `resolve`، وإن السؤال يرجع يظهر بعد `resolve`.
  - الفحص (شكل الطلب، والـ JSON).
  - `GapRecorder`: مبيرميش exception، ومش بيسجّل لو `missing_information=false`.
  - الـ chat handler: بيسجّل `off_topic` لما الفحص يرفض، وبينادي `reviewReply` بعد `done` بس.
  - الـ routes: الاتنين staff-only.
- **Angular:** صفحة الأسئلة (التبويبين، والعدد، وزرار "تم")، و `GapsApi`.
- **تجربة حقيقية:**
  1. نسأل 3 أسئلة مالهاش إجابة، ونكرر واحد منهم بصيغة فيها همزة مختلفة.
  2. نتأكد إنهم ظهروا في الصفحة متجمّعين صح.
  3. سؤال برّه الجمعية يظهر في التبويب التاني.
  4. نضيف إجابة واحد منهم في `knowledge/`، ونعمل restart، ونسأله تاني.
  5. نتأكد إنه اترد عليه ومااتسجّلش.
