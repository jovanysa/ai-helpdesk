# Phase 2 Tickets & Staff Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Customers open tickets (from the chat or a form), the local model classifies them, and logged-in staff list, filter and update them.

**Architecture:** SQLite via built-in `node:sqlite` behind small repository classes. API logic lives in plain handler functions returning `ApiResult` (`{ status, body?, setCookie? }`); `api-router.ts` is thin Express glue, so tests never import Express (same pattern as phase 1). Angular uses `HttpClient` + Reactive Forms; staff pages are lazy, guarded by `authGuard`, and rendered client-side only.

**Tech Stack:** Angular 22, Express 5, `node:sqlite`, `node:crypto` (scrypt, sha256), Ollama `/api/chat` with JSON-schema `format`, Vitest via `ng test`.

**Spec:** `docs/superpowers/specs/2026-10-02-tickets-design.md` (schema in §4, API table in §5, classifier rules in §6, screens in §7, errors in §8).

## Global Constraints

- No new npm dependencies.
- All SQL uses `?` parameters. Column names may only come from fixed in-code lists.
- Server files under `src/server/`; anything a spec imports must not import `express`.
- Enum values (exact): status `new|in_progress|resolved`; category `donation|volunteering|help_request|complaint|other`; priority `low|medium|high`; classification `pending|done|failed`.
- Arabic labels (exact): status جديدة / قيد المتابعة / تم الحل; category تبرع / تطوع / طلب مساعدة / شكوى / أخرى; priority منخفضة / متوسطة / عالية.
- Ticket validation: name 2–100 trimmed; phone → Arabic-Indic (U+0660–0669) and Persian (U+06F0–06F9) digits to ASCII, spaces removed, must match `^\+?[0-9]{8,15}$`, stored normalized; description 5–2000 trimmed; transcript optional, 1–20 items of `{ role: 'user'|'assistant', content: string ≤ 8000 }`.
- Session cookie (exact): `sid=<token>; HttpOnly; SameSite=Strict; Path=/; Max-Age=604800`. Clearing uses the same with an empty value and `Max-Age=0`. DB stores sha256(token) hex. TTL 7 days.
- Password hash format: `scrypt$<salt hex>$<hash hex>`, 16-byte salt, 64-byte key, compared with `timingSafeEqual`.
- Error copy (exact): login failure `البريد أو كلمة المرور غير صحيحة`; generic `حصل خطأ، حاول تاني.`; ticket success `تم تسجيل طلبك رقم #<id>، هيتواصل معاك موظف قريب.`
- Never `git add angular.json`. Add explicit paths only.
- Tests: `npx ng test --watch=false`. Server tests use a real `openDatabase(':memory:')`.

## Review Focus

1. The AI classification finishes **after** a staff member already set category/priority by hand → the staff choice must win. Test in Task 3 (`applyClassification` only updates rows still `pending`).
2. Customers type the phone in Arabic digits (`٠١٠٠١٢٣٤٥٦٧`) or with spaces → accepted and stored as `01001234567`; a phone of only spaces is rejected. Tests in Task 3 (server) and Task 6 (client validator).
3. Session expires while a staff page is open → the next request's 401 sends them to `/staff/login`, and a 401 from `/api/auth/*` itself never triggers a redirect loop. Test in Task 6.
4. Escalating from the chat after a very short last message (e.g. `hi`) → the server's 5-char minimum must not reject it; a fallback description is used. Test in Task 7.
5. Staff email typed with different case or surrounding spaces (`  Admin@AlKhair.example `) → login still works. Test in Task 2.
