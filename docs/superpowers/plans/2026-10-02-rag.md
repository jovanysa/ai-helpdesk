# Phase 3 RAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The chat answers only from `knowledge/*.md`, retrieved per message with local embeddings, and refuses everything else with a fixed sentence.

**Architecture:** Markdown files are split on `##` into chunks, embedded with Ollama `granite-embedding:278m`, and cached in SQLite keyed by content hash. Each chat request embeds the customer's question, takes the top 3 chunks by cosine similarity, builds the system prompt from them, emits a `sources` SSE event, then streams the reply as in phase 1.

**Tech Stack:** Ollama `/api/embed`, `node:sqlite` BLOBs, `node:fs`, Angular Signals. No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-02-rag-design.md` (decisions in §4, file format §5, table §6, errors §7).

## Global Constraints

- No new npm dependencies. Server files under `src/server/`; anything a spec imports must not import `express`.
- Env vars: `OLLAMA_EMBED_MODEL` (default `granite-embedding:278m`), `KNOWLEDGE_DIR` (default `join(process.cwd(), 'knowledge')`).
- Top K = 3, no similarity threshold.
- Search text: last user message; if its trimmed length < 20 and an earlier user message exists, `previous + '\n' + last`.
- Refusal sentences (exact): AR `معنديش المعلومة دي. أقدر أساعدك في أي سؤال عن جمعية الخير، أو كلّمنا على 0100 000 0000.` EN `I don't have that information. I can help with questions about Al-Khair Foundation, or call us on 0100 000 0000.`
- Missing-model log (exact): ``Embedding model "<model>" is not downloaded. Run `ollama pull <model>`.``
- SSE `sources` event (exact shape): `{"type":"sources","sources":[{"title":"…","file":"…"}]}`, sent before the first token.
- UI line (exact prefix): `اتقرا من: ` followed by titles joined with `، `.
- Never `git add angular.json`.
- Tests: `npx ng test --watch=false`.

## Review Focus

1. A short follow-up ("وبالفيزا؟") must search with the previous question too, or it retrieves nothing useful. Test in Task 3 (`buildSearchQuery`).
2. A knowledge file edited or removed while the server was stopped → changed chunks re-embedded, removed chunks deleted, so stale facts are never served. Test in Task 2.
3. Embedding model not downloaded / Ollama down at the first request → 503 with the pull hint, and the next request after fixing it works without restarting. Tests in Tasks 1 and 2.
4. Empty or missing `knowledge/` folder → no crash; prompt says `(none)` and the model refuses. Tests in Tasks 1–3.
5. The client keeps `sources` on assistant messages; they must not leak into requests (`/api/chat` and the escalation transcript send only `role` and `content`). Test in Task 4.

  - `interface KnowledgeSource { file: string; title: string; content: string; score: number }`
  - `class KnowledgeBase(db: DatabaseSync, embed: EmbedFn, loadChunks: () => KnowledgeChunk[], model: string)`
    - `search(query: string, k = 3): Promise<KnowledgeSource[]>` — ensures the index (memoized promise, cleared on failure), embeds the query, returns top k by cosine, highest first

  - `KnowledgeSearch = Pick<KnowledgeBase, 'search'>` (type used by the chat handler)
